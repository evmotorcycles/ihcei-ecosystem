The one idea underneath all of it

Most software asks you to trust that whoever wrote it was careful. These tools are built so that carelessness is structurally impossible rather than merely discouraged.

Ordinary code

0.800

A real function scoring a software project. It quietly reads the project's own marketing description and adds half a point. It has no bugs. It passes every check. The number arrives looking exactly like a measurement.

The same intent, governed

0.300

The honest answer. The self-description was deleted from the record before the function ran — not ignored by policy, not skipped by a careful author. It could not have been read.

Rule 1

No bare answers

Every result carries its confidence, its reasons, and a receipt. A lonely number cannot be argued with, because it has no reasons attached.

Rule 2

Blind means deleted

Not "ignored". Removed before the check begins, and the removal is written into the receipt so an auditor can verify it happened.

Rule 3

Two checks must be two

If your two sources secretly carry the same information, you looked twice and learned once. The program halts rather than sounding twice as sure.

Rule 4

"I don't know" is an answer

Declining is a normal, successful result — not a crash. If saying it is expensive, software stops saying it and starts guessing.

Rule 5

Gates written first

What would count as failure is fixed and hash-locked before the data is seen. Change it later and the hash changes visibly.

Rule 6

Nothing learns from itself

A system trained on its own output measures its own consistency, not the world. Ours refuses those labels outright.

What Novora cannot do

This section is not a disclaimer. It is the most useful page here, because a tool that hides its limits gets trusted once — wrongly — and then abandoned.

Read this before relying on anything
  1. Nothing here knows whether something is true. The tools check whether a claim is checkable, whether permission was granted, whether a record was altered. A sentence can pass every check and still be false.
  2. These are screens, not judges. They match patterns in text. They do not understand what you paste, and they can be wrong in both directions.
  3. There is no vision model. The image reader knows the pixel dimensions. A chart, a contract photo and a cat are the same thing to it.
  4. No video can be fetched. There is no network by design. Open the video, copy the transcript, paste it in — that path is honest and it works.
  5. Structure is not safety. For anything touching health, money, law or chemicals, a well-formed claim and a safe one are different things. The tools say so every time, and then you still need a qualified person.
  6. The record is tamper-evident, not tamper-proof. It makes editing visible. It does not prevent it.
  7. We make no claim about market size or valuation. Those depend on things no repository can measure, and any figure would be invented.
