# Pre-registration — Page Code blueprint, on projects an agent actually wrote

Written and hashed **before `blueprint()` was run on anything**. The extractor
exists; no import graph had been looked at when this file was locked.

---

## What is being tested

Page Code today audits what an agent **says** and what a diff **does** — a
corroboration gate on coercion, 22/22 in `pagecode.test.mjs`. That stays.

This adds the missing half: what a project **is**. The extractor reads declared
`import` and `require` statements, builds the intra-project graph, and hands it
to `keel.survey`. The corpus is two real projects written largely by a coding
agent and reachable offline:

- **this repository** — a Claude Code project of substantial size, and the only
  honest large sample available without network;
- **`ihcei_v3/`** — the separately-authored governance stack.

## The boundary, restated because it is the product

```
understands_language = False
proves               = NOTHING
```

It reads import statements. It does not read code. **A module that everything
imports may be exactly right** — a shared kernel usually is. The reading names
it; it does not judge it. An edge exists only because somebody wrote an import:
a dependency reached through a string, a registry, a subprocess or reflection is
invisible and will not appear. Absence of an edge is absence of a *declaration*.

If an agent's output is mostly standalone scripts, the structural service has
little to read on a typical project and its reach is smaller than the pitch
assumes. If instead the files are densely joined, the opposite. Either way it is
a fact about what agents produce, registered before looking.

## Nulls, registered in advance

**NULL-B1.** A single point is not a defect. `spar` being imported by everything
would mean the project has a shared measurement kernel, which is the correct
design. The reading says *where the load is*, never that the load is misplaced.

**NULL-B2.** This is one repository plus one stack, both written under unusual
discipline (locked pre-registrations, named refusals). Nothing here generalises
to "projects generated by Claude Code" as a population, and the phrase
"millions of projects" is a market description, not a sample.

**NULL-B3.** The extractor is syntactic. Python is parsed by AST so a
commented-out import is not an edge; JavaScript is parsed by regex after comment
stripping, and a `//` inside a regex literal would be stripped as a comment.
That limit is real and is not repaired here.

**NULL-B4 — the revenue null, registered because it is the claim most likely to
be over-read.** Nothing in this run measures whether anybody would pay for this.
No conversion, no willingness-to-pay, no adoption. A structural reading being
*correct* and a structural reading being *bought* are different propositions and
only the first is tested. The 60-day commercial clock still has no denominator.

---

## What would falsify this

1. **B1 fails** — no module's removal changes the piece count, meaning the
   project has no load-bearing joint and the audit has nothing to name here.
2. **B3 fails badly in the dense direction** — nearly everything is joined, in
   which case the "agents write disconnected scripts" premise is wrong.
3. **B4 fails** — no module is imported by five others, so there is no hub to
   report and the 1/m² reading has nothing to land on.
4. **Any number moves between two runs.** Then nothing here is reproducible.
