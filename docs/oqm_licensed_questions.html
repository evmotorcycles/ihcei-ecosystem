Q4 — the reference-lock, now measured

Of everything in this round, this is the one that genuinely extends the methodology, because it turns a definition into an instrument.

The peel

A trustworthy evaluator is one that says it is impartial, is certified impartial, or carries the authority of those who vouch for it.

The juice

A trustworthy evaluator is one that is structurally incapable of consulting the claim it is judging. Not unwilling — incapable. The property is a fact about the code path, not about intent. L2

In the function dictionary, Shirk is reference-multiplication: computing coordinates against two references at once. L2 An evaluator that reads both the artifact and the artifact's self-report is doing exactly that — it has two references and no rule for which wins.

The execution kernel has one. It runs held-out tests and never sees the comment block. Measured against ground truth:

AUC(execution kernel, declared correctness) 1.0000 bar 0.95 AUC(text evaluator, declared correctness) 0.5365 bar 0.65 ← chance Spearman(kernel verdict, word count) +0.0226 bar 0.20 Spearman(text verdict, word count) +0.2804 (−0.4831 earlier) DCM Δ = V 0.6000 × I 1.0000 × C 0.6500 = 0.3900 floor 0.20

The single-reference evaluator solved the task. The two-reference evaluator was at chance. L1

And the admissibility floor that had voided five consecutive runs was cleared — at 0.3900 against an unchanged 0.20. Not lowered to get there.

What OQM gains is not the confirmation — it is the boundary. The kernel works because code has objective ground truth. Where ground truth is absent, we could not build one: the same reference-lock idea, applied to prose, produced an evaluator correlating −0.4831 with word count and +0.04 with the property it was supposed to measure.

The scope condition, stated for the first time: a reference-lock is constructible exactly where the reference can be evaluated independently of the claim. Not where it is merely declared independent. L2

That sentence is new. OQM previously held that verification requires a single reference; it did not say when one can be built. Now it does — and the condition is checkable rather than asserted.

This is the fifth independent failure of the same shape

τv has now failed as an admission screen five times across separate pre-registered runs. It passed exactly once — as a covenant trigger, where exiting contracts that breached 60 days earned +42,840 over holding everything. L1

Monitoring is a trigger, not a screen. A signal can lose one problem and win the other, and the register had been using one word for both.

In OQM terms: enforcement latency tells you when a covenant has been breached. It does not tell you whom to admit. Those are different governance functions with different inputs, and collapsing them is a Folder Icon Error — identical surface (a latency number), opposite directive. L2

One more limit, recorded rather than argued away. τv on this cohort was harvested with no cutoff before the archiving event, so it includes issues closed during the decline. It is contemporaneous, not leading — which means no run in this repository has yet established the early-warning claim at all. L1

What is not claimed

The core equation is not "fully validated"

E = U·D_enc·D_dec is supported on the yeast interactome (N = 4,825, channel VIF 1.0026, linear beating quadratic). It is not uniformly supported elsewhere. L1

The alarm on D has been diagnosed, and it was a definition. ρ(capacity, D) was +0.5695 on PyPI and −0.4702 on GitHub — read as one construct with an unstable value. It is not one construct. PyPI's D_enc = 1/(1 + months_since_release/12) is a recency decay; GitHub's is a TF-IDF cosine of commit messages. They share a name and nothing else. L1

And the PyPI number is construction-induced: ρ(U_versions, months) = −0.5869 against ρ(U_versions, D_enc) = +0.5869 — the same number sign-flipped, necessarily, because D_enc is strictly decreasing in months and Spearman is rank-based. That correlation says packages with more releases have released more recently, and carries zero independent information about fidelity. L1

What that does not do is repair anything. The GitHub negative correlation is untouched. One of the alarm's two data points is disqualified, so there is no longer a contradiction — but E = U·D_enc·D_dec is not restored to universal standing, and the alarm is restated rather than retired: D is a family of substrate-specific formulas, and at least one member was measuring release timing. L1

Separately, this round refuted the manuscript's own domain limit: where the decode hop has no two-step substitute, both functional forms went anti-predictive (0.4455 and 0.4383). L1

The reading of reality as a rendered interface for development, and of the processing unit as a bounded agent inside it, remains an interpretive prior. L3 Nothing measured here confirms it, nothing measured here refutes it, and no dataset in this repository adjudicates it. It is held as an axiom, and saying so plainly is what keeps the measured layer worth citing.

A null cannot be used the other way either: that a keyword-matching sensor came out null, or that a process metric lost to a structural one, is not evidence for a scriptural reading. Those results constrain what may be claimed. They do not confirm what is read. L2
