Correction — a published figure retired

“Quadratic anti-predictive, AUC ≈ 0.47” is a fitting artifact, not a finding.

Under a converged single-term fit the quadratic scores CV AUC 0.5911 — above chance, not anti-predictive. The only way to reproduce a sub-chance value is the non-converged multivariate U + D + D² fit, which returns in-sample 0.4275 — essentially the published 0.47.

The qualitative conclusion LISM relies on — adding D² does not improve prediction — survives (0.591 < 0.666). The specific number does not, and should stop being quoted as evidence of anti-predictive behaviour.

GitHub 992 — still open, and a prediction I missed

No 992-row labelled artifact is committed anywhere; the largest labelled JSON holds 22 rows. Refetching needs ~2 API calls per repository at 60 requests/hour unauthenticated — roughly 33 hours — so it was not attempted.

The N = 992 result (750 fail / 242 survive, AUC ≈ 0.73) must not be cited as offline-reproducible from this repository.

This does not mean the original analysis was wrong — it may have been run correctly against data never committed here. It means this repository cannot substantiate it, which is the only thing a reproducibility claim can rest on.

Missed prediction — recorded, not rescued

I pre-registered N ≥ 35 for the union cohort. It reached 33.

The direction held strongly — median τ_v 45.4 d failed vs 4.3 d survived — and failures rose from 4 to 9, materially improving power. But the number I committed to was missed.

The threshold was not moved from 35 to 30. The test asserts union_N == 33 and that this gate stays in missed_predictions, so rescuing it later breaks CI.

Knowledge 793 — retracted as real, and the thesis falsified

Two separate things, which must not be conflated. The retraction: the committed N = 793 fixture is synthetic (synthetic: true, seed: 20260720). Any narrative citing it as a real Stack Exchange measurement is not supported here. It serves only as a labelled estimator control — and it does that job, recovering independent hops at VIF 1.0032.

The falsification (K1): the pre-registered claim that fidelity-adjusted capacity would out-predict raw status was tested on four real substrates and failed badly.

Real substrateρ status aloneρ fidelity-adjusted
Hugging Face · likes → downloads (N=19)+0.4035+0.0123
GitHub · stars → forks (N=28)+0.8763+0.5140

Diagnosis, not a rescue. The only available yield proxies — downloads and forks — are themselves popularity measures. Popularity predicts popularity. The fidelity legs measure trustworthiness, a different axis. The thesis conflated reach with quality.

What survived is sharper: capacity does not buy fidelity (K3: PubMed ρ = +0.19, bioRxiv ρ = −0.09), and prestige ordering ≠ verified ordering (K4: all five of GitHub’s most-starred repos sit below the fidelity floor). K2 partially failed and was not papered over — GitHub VIF 1.1741 exceeds the pre-registered 1.10 gate. Threshold not moved.

The corrected conclusion: it is not that fidelity predicts reach — it plainly doesn’t. It is that reach and trustworthiness are separate, measurably different orderings, which is exactly why an evaluator must measure fidelity separately instead of inferring it from popularity.

Digital swarm — a label, plus a test that can fail

The swarm source self-declares “simulates the swarm” (500 nodes, fixed seed). A seeded simulation reproducing itself is a code-correctness check, not evidence. In the test suite this gate is explicitly marked falsifiable: false, and an assertion prevents it from ever being counted as support.

So the swarm’s substantive claim — linear ≥ quadratic on a dependency network — was tested on something real instead: a 434-package PyPI dependency graph.
